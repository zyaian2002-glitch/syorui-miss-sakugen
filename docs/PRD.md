# 書類ミス削減 PRD（ドラフト v0.2）

> ステータス：**未承認ドラフト**。Haru の合意前は作り始めない。
> 最終更新：2026-10-30

## 1. デザイン戦略（合意済み）

### ターゲットと本質的欲望
- **対象：** Haru 本人（自分で作成する書類）
- **本質的欲望：**「ミスを出さない」という**安心感**
  - 「確認せずに出す人」と思われたくない
  - 修正や訂正の手間をなくしたい

### ゴールライン
- 対象の書類：Excel / Word。月に15〜20枚（うち8〜10枚は同じ様式、残りは毎回違う様式）
- 実際に起きたミス（チェックすべきもの）：
  1. **日付・年号の古いまま残り**（例：令和8年なのに令和7年のまま）
  2. **印刷の見切れ**（Excel で右端の列が切れる）
  3. **漢字の誤変換・誤字脱字**
- **価値になる境界線：** 上の3種類のミスが、印刷する前に自動で指摘される

### デザインプリンシプル（優先順位）
1. **見逃しゼロ ＞ 誤検知の少なさ**（多少うるさくても、怪しいものは全部出す）
2. **思い出さなくても動く ＞ 自分で起動する**（チェックし忘れが一番のリスク）
3. 正直さ：機械で確実に見つけられるもの（日付・印刷）と、確率でしか見つけられないもの（漢字）を分けて示す

## 3. 仕組みの仮案（未確定）

| ミス | 方式 | 確実性 |
|---|---|---|
| 日付・年号 | マクロ：今年以外の年号・年、曜日と日付のずれ、和暦と西暦の混在を全部指摘 | 高い |
| 印刷の見切れ | マクロ：印刷範囲の外にあるデータ、想定より多いページ数、1列だけ別ページに出る状態を指摘 | 高い |
| 漢字・誤字 | AIに本文を読ませる（推奨案A：マクロが本文と指示文をクリップボードにコピー → Claude に貼り付け） | 中程度（ゼロ保証は無理） |

- 起動のきっかけ：**印刷ボタンを押した瞬間に自動でチェックが走る**（Excel/Word の印刷前イベントを個人用マクロブック / Normal.dotm で受け取る）
- 問題がなければ一瞬で終わる。問題があれば一覧を表示して「それでも印刷するか」を確認する
- **Haru が使っているときだけ動く**（実装方法は §5 Q1 の回答次第）

### 漢字チェックとAIの接続（検討メモ）
- 月額課金（Claude / GPT / Gemini）には、Excel・Word から直接呼べる「API」は**含まれない**。API は別契約で従量課金
- 案A（推奨・v1）：コピーして貼り付ける方式。追加費用なし、APIキー不要、会社PCの設定変更も不要。ただし貼り付けの1手間が残る
- 案B（将来）：マクロから Claude API を直接呼ぶ。手間ゼロだが、APIキーを会社PCに置くことと通信の許可について、会社の確認が必要
- 案Aの弱点：「思い出さなくても動く」原則と矛盾する → 印刷前チェックで「漢字チェック未実施」を毎回警告して補う

## 4. 文脈設計（UXの4ステージ）※ 記入待ち
- **知る：** 自分用なので不要。ただし「存在を思い出す」必要がない作りにする
- **アクセスする：** 職場のPCで、書類を作り終えて印刷ボタンを押した瞬間
- **使う：** ①日付・年号チェック ②印刷の見切れチェック ③漢字チェック用のコピー機能。問題がなければ何も表示せず、そのまま印刷される
- **結果（残る感情）：**「これで出して大丈夫」という安心感（合意済み）
